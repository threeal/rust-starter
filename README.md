# Rust Starter

A minimal template for building a [Rust](https://www.rust-lang.org/) library with an optional CLI. Ships pre-configured with formatting, linting, 100% test coverage enforcement, pre-commit hooks, and CI.

## Getting Started

Create a new repository from this template on GitHub using [this link](https://github.com/new?template_name=rust-starter&template_owner=threeal), or clone it locally and point it at your own remote.

## Setup

Install [rustup](https://rustup.rs/), then install the toolchain pinned in `rust-toolchain.toml`:

```sh
rustup install
```

Install [cargo-tarpaulin](https://github.com/xd009642/tarpaulin) to run the test suite with coverage:

```sh
cargo install cargo-tarpaulin
```

Install [Lefthook](https://lefthook.dev/) and [dprint](https://dprint.dev/), then register the pre-commit hook:

```sh
lefthook install
```

## Customizing

Replace or extend the template files to fit your project:

- **`src/`** — Replace the placeholder library, CLI, and tests with your own code.
- **`Cargo.toml`** — Update the package name, description, version, authors, and other metadata.
- **`CLAUDE.md`** — Replace with guidance specific to your project.
- **`LICENSE`** — Replace with your preferred license, or keep the [Unlicense](https://unlicense.org/).
- **`README.md`** — Replace with a description of your project.

If your project doesn't need a CLI, remove `src/main.rs`, its `exclude-files` entry in `tarpaulin.toml`, the `clap` dependency in `Cargo.toml`, and the binary build in `.github/workflows/release.yaml`.

## Development

Run the tests with coverage through tarpaulin:

```sh
cargo tarpaulin
```

The project enforces 100% code coverage, excluding files listed under `exclude-files` in `tarpaulin.toml`.

Each `git commit` runs the pre-commit hook registered during setup, which checks your changes and fixes what it can in place. If it fails, fix any reported issues, re-stage the changed files, and commit again.

After committing, push to `main` or open a pull request from another branch — CI will run the same checks across all files, plus additional checks of its own.

## Releasing

Update the version in `Cargo.toml`, then push a version tag to create a draft release with notes generated by GitHub and the CLI binary attached. Review the draft on GitHub, edit the notes if needed, and publish it when it's ready.

To also publish to [crates.io](https://crates.io/), add a [crates.io API token](https://doc.rust-lang.org/cargo/reference/publishing.html#before-your-first-publish) with publish rights as the `CARGO_REGISTRY_TOKEN` repository secret. Publishing the draft then publishes the crate to crates.io.

Once the crate exists on crates.io, you can replace the token with [trusted publishing](https://crates.io/docs/trusted-publishing): add a trusted publisher on crates.io for your repository and `publish.yaml`, then delete the `CARGO_REGISTRY_TOKEN` secret after a release has published through it.

If your project isn't published to crates.io, remove `.github/workflows/publish.yaml`.
